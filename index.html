四层对照：定义、触发、能改什么

system prompt · 宿主底线

这是平台底层写死的提示。你改不了。它每次都会自动进上下文，管的是整机行为底线——不是项目里能编排的那一层。

  • 是否可改：不可改
  • 触发：每次自动读入
  • 内容：平台原则与硬约束
  • 场景：不可编排的宿主底线

agents 规则文档 · 人设指针

也就是线上的 profile／description／人设。用户可以改，而且权重很高——它是唯一每次对话都会自动读进去、且我们能改的那一层。

  • 写什么：岗位职责；何时读 agent.md；何时加载哪个 skill（含 id）
  • 硬纪律：人设里没提的，执行时不要默认去读
  • 作用：单 bot 人设，在此写明开工指针

skills · 标准动作包

全局共享、可安装、按需调用。它靠 name 和 brief description 做意图匹配；匹配上了才读正文。适合某一类固定任务的标准动作。

  • 内容形态：触发条件 ＋ 执行步骤清单／方法
  • 输出约束：松紧取决于正文流程写得严不严
  • 场景：单类任务的标准动作

xxx.md · 项目章程族

包括 agent.md、SOP.md、项目章程.md 等磁盘上的项目／岗位规则说明书。不会每次自动全文灌进上下文。

  • 触发：任务匹配，且 profile 提及或口头触发才读；读则全文（没有 skill 那种「先看简介」两截机制）
  • 内容：原则、优先级、行业隔离、跨 bot 协作章程、配合流程、验收标准
  • 场景：agent 协作规矩与项目章程

关键对照 · 最容易混的一对

agent.md 与 skill：本质区别

📒 agent.md

规则说明书

项目或岗位章程；可写跨 bot 协作与配合流程。内容偏准则：原则、优先级、行业隔离、配合标准、验收标准。

生效：profile／description 提及，或口头触发

VS
⚙️ skill

操作流程

可复用的标准动作，适合固定任务。写触发条件与执行步骤清单。

生效：name＋brief description 意图匹配后触发

松紧：取决于正文写得严不严

一句话：agent.md 管「协作规矩和项目章程」；skill 管「单类任务的标准动作」。
