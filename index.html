Agent 编排，其实是五层

前四层管「怎么做、按什么规矩做」；第五层「外挂知识库」管「业务事实与素材从哪取」——SQL 精确查 ＋ 向量语义找，结果回灌大模型再判断。

想象你在带一个剧组：平台有不可改的安全底线；每个角色有人设；技能包可随时调用；项目还有章程；另外还有外挂资料库——订单表、风格段、FAQ，按需查，不替代前四层。

五层对照：定义、触发、能改什么

system prompt · 宿主底线

平台底层写死的提示。你改不了。每次自动进上下文，管整机行为底线——不是项目里能编排的那一层。

  • 是否可改：不可改
  • 触发：每次自动读入
  • 场景：不可编排的宿主底线

agents 规则文档 · 人设指针

线上 profile／description／人设。用户可改、权重很高——唯一每次自动读、且我们能改的一层。

  • 写什么：岗位职责；何时读 agent.md；何时加载 skill；何时查哪类知识库
  • 硬纪律：人设没提的，执行时不要默认去读／去查

skills · 标准动作包

全局共享、按需调用。靠 name 和 brief description 意图匹配后读正文。可编排「如何查库」的步骤。

  • 内容：触发条件 ＋ 执行步骤清单
  • 输出约束：松紧取决于正文写得严不严

xxx.md · 项目章程族

agent.md／SOP.md／项目章程.md 等。不每次自动灌入；profile 提及或口头触发才读全文。

  • 内容：原则、行业隔离、跨 bot 协作、验收标准、知识库触发与隔离规则
agent.mdSOP.md项目章程.md

外挂知识库 · 第五种编排方式

通过外挂接入数据／素材层。底层两类：① SQL 精确匹配字段（如订单号查订单）；② 向量库 语义相似度检索（如找相近风格段）。结果以 tool_result 回灌模型，常需多轮。

  • 是否可改：库内容／索引／连接可维护；何时查靠人设／skill／md 声明
  • 触发：非每次自动；任务需要时调工具查询
  • 约束：只读优先、限行、限条；裸结果通常不当最终答复
关键对照 · 最容易混的一对

agent.md 与 skill：本质区别

📒agent.md

规则说明书

项目或岗位章程；可写跨 bot 协作。偏准则：原则、优先级、行业隔离、验收标准；也可写清何时查外挂库。

生效：profile 提及或口头触发

VS
⚙️skill

操作流程

可复用标准动作。写触发条件与步骤清单；查库类任务也可落成 skill 步骤。

生效：name＋简介意图匹配

一句话：agent.md 管协作规矩；skill 管标准动作；外挂知识库管业务事实与素材从哪取。
第五层 · 检索怎么跑

外挂知识库完整检索流程

不是「查一次就结束」。真实链路是：取数 → 回灌 → 大模型判断够不够 → 不够再查。

1SQL 结构化查询

精确匹配字段值。
例：订单号 → 订单状态／金额；角色名 → 定妆图路径。

精确字段命中DuckDB／业务库
→
2向量语义检索

文本向量化后按语义相近度查找。
例：找「开场反差钩子」相近风格段／FAQ。

语义相近top-kChroma／Qdrant
→
3大模型判断

结果以 tool_result 回灌上下文。
判断：够不够答？要不要再查？再组织自然语言答复。

回灌推理多轮非裸结果终答
⟲ 不够时回到步骤 1 或 2（例如先查订单表，再查物流表；或改 query 再向量检索）。最多设补查上限，失败则回退人工／现有索引。
第五层 · 什么时候用

四种典型使用场景

A · 精确字段 → SQL

需要订单号、ID、状态码、角色名→路径等精确命中时，走结构化查询。不靠「感觉相似」。

B · 语义相似 → 向量

需要按意思找相近内容：风格段、FAQ、案例、情绪／运镜公式。适合「像不像」而不是「等不等于」。

C · 两者结合

先 SQL 定位再向量扩展（先锁定订单／项目，再找相关说明）；或先向量筛再 SQL 精确（先缩小语义范围，再查字段确认）。

D · 结果不确定 → 模型再判

查到了仍可能不够、不相关或失效。由大模型判断是否补充查询、换表、改 query，或回退人工——不要把裸查询结果直接当终答。

边界提醒：外挂库解决「取数／供料」；不替代参考图＋文字锁去修穿帮，也不自动解决 Seedance／画布导入问题。
第五层 · 检索质量靠什么

决定检索质量的五个要素

A · 参数

top-k／阈值／embedding

取几条、相似度阈值卡多严、用哪套 embedding 模型——直接决定召回面与噪音量。写前建议 top-k=2，宁缺勿滥。

B · 检索方式

纯向量／关键词／混合

纯向量擅长语义；纯关键词擅长专有名词；混合检索（向量＋关键词）往往更稳，尤其专名＋语义并存时。

C · 元数据过滤

先筛标签再语义搜

按项目、类型、行业、情绪标签先过滤，再做向量搜。硬隔离 TVC／漫剧，防止串库。

D · 数据质量

切片策略＋索引同步

文档怎么切、段多长、是否带来源；文件更新后索引是否及时更新。路径失效、过期片段要能标失效。

E · 回灌判断

大模型二次把关

召回只是候选。模型要判断相关／不相关／是否补查，再组织答复。附引用 ≠ 自动过稿。

实践口诀

限量 · 隔离 · 回退

每次少取；行业／项目先滤；查到／无结果／不相关／失效／工具失败五类都要有回退，并记成本再扩。

记住这张五层地图

平台底线不可动；人设是每次必读的可编排入口；技能包按意图上场；项目 md 写协作规矩；外挂知识库在需要事实／素材时上场——SQL 精确、向量语义、模型判断够不够，不够再查。

编排入口

改 profile：何时读 md、加载 skill、查哪类库

协作规矩

跨 bot 流程、行业隔离、验收标准进 agent.md

取数供料

SQL／向量限量回灌；五类失败有回退；裸结果非终答

收束 · 留给你带走的思考

思考点

讲完五层地图，先别急着关页——对着自己的项目想两遍。

思考点 1

如何设计自己的 agent？

agent 编排层面，我们可动的部分有哪些？

提示：人设／profile · skills · xxx.md · 外挂知识库（连接与触发声明）——对照 system 不可动那一层。

思考点 2

如何设计 agent 的规则？

哪些规则每次都读（常驻）？哪些是需要触发的（按需）？

提示：常驻 ≈ system＋profile；按需 ≈ skill（意图匹配）· agent.md（提及／口头）· 外挂库（任务需要时查）。

把答案写进你自己的 profile 与 agent.md：可动的写清楚；常驻与按需的边界写清楚——比多装几个 skill 更重要。
